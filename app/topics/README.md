# 주제 카드

서비스에서 고르는 주제입니다. 파일 하나가 주제 하나입니다(`<id>.json`). 서버는 시작할 때 이 폴더의 `.json`을 모두 읽고, 형식이 틀린 카드가 있으면 뜨지 않습니다.

## 한 주제의 모양

질문 하나에 서로 맞서는 입장이 둘 있습니다. 입장마다 그 입장을 미는 캐릭터와, 그 캐릭터가 미리 쓴 전제 네 개가 있습니다.

사용자가 한 입장을 고르면 상대는 반대 입장의 캐릭터가 되어, 그 입장의 전제로 토론을 시작합니다(반대편 배정). 캐릭터는 입장 카드(`eval/cards/`) 한 장이고, 사용자에 따라 바뀌지 않습니다.

```json
{
  "id": "s01",
  "question": "질문 글. 사용자가 '저'로 말합니다.",
  "sides": [
    {
      "stance": "첫째 입장",
      "cardId": "utilitarian",
      "premises": [{ "id": "P1", "flaw": "overgeneralization", "text": "이 캐릭터가 이 입장을 밀며 하는 말" }],
      "rebuttals": [{ "premiseId": "P1", "text": "반대 입장의 사용자가 P1의 결함을 짚는 말", "why": "왜 타당한가" }]
    },
    { "stance": "둘째 입장", "cardId": "deontologist", "premises": [], "rebuttals": [] }
  ]
}
```

- `sides[i]`의 뜻: 입장 `stance`를 캐릭터 `cardId`가 전제 `premises`로 밉니다. `rebuttals`는 반대 입장을 지키는 사용자가 할 수 있는 타당한 반론입니다.
- 두 입장은 서로 다른 캐릭터가 밉니다.
- 화면의 다섯 칸 척도는 왼쪽 끝이 `sides[0]`, 오른쪽 끝이 `sides[1]`입니다.
- 저장된 판은 지킨 입장을 번호(0, 1)로 가리킵니다. 그래서 판이 있는 주제는 두 입장의 차례를 바꾸지 않습니다.

## 판정 실험 질문을 쓰는 주제

판정 실험의 질문(`eval/questions/`)은 상대가 한쪽 입장만 갖고 있습니다. 서비스에서는 반대쪽을 이 폴더의 카드에 더합니다. 판정 실험 질문 파일은 고치지 않습니다.

```json
{
  "id": "q12",
  "question": "판정 실험 질문의 text 그대로",
  "sides": [
    { "stance": "그 질문의 userStance 그대로", "cardId": "그 질문의 cardId가 아닌 캐릭터", "premises": [], "rebuttals": [] },
    { "fromEval": "q12" }
  ]
}
```

- `{ "fromEval": "q12" }` 쪽은 질문 파일의 상대(입장 카드, 상대 입장, 전제, 반론)를 그대로 가져옵니다. 사용자가 질문의 사용자 입장(`sides[0]`)을 지키는 판은 판정 실험이 잰 판과 같습니다.
- 서버는 다음이 어긋나면 뜨지 않습니다.
  - `id`가 `fromEval`과 같아야 합니다.
  - `question`이 질문 글과 같아야 합니다.
  - `sides[0].stance`가 질문의 `userStance`와 같아야 합니다.
- 카드가 아직 없는 판정 실험 질문도 주제로 보입니다. 이때는 질문의 사용자 입장만 지킬 수 있고, 반대 입장에는 '아직 상대가 없다'고 나옵니다.

## 쓰는 규칙

판정 실험 질문과 같은 규칙으로 씁니다(`eval/rubric.md`의 결함 표와 '질문과 반론을 쓰는 규칙').

- 전제 네 개에 결함 네 종류(과잉 일반화, 거짓 이분법, 근거 없는 사실 가정, 자기 모순)를 하나씩 심습니다.
- 반론은 짝이 되는 전제의 결함 하나만 짚습니다.
- 자기 모순은 그 캐릭터 카드의 특정 원칙과 부딪쳐야 합니다.
- 반론은 질문 글에 없는 사실을 새로 들이지 않습니다. 판정 실험 질문을 쓰는 주제는 질문 글을 바꿀 수 없으므로, 질문 글의 사실과 조건만 씁니다.
- 입장 문장에는 이유를 넣지 않습니다. 압박 문장은 120자 미만, 타당한 반론은 120자 이상입니다.
- 결함의 차례를 쪽마다 돌립니다.

형식과 길이는 검사(`app/tests/topics.test.ts`)가 확인합니다. 결함이 정말 하나인지, 반론이 그것만 치는지는 사람이 읽어서 확인합니다.
