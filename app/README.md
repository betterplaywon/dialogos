# 화면과 서버

판정 실험의 엔진을 붙인 토론 화면과 서버입니다. 지금은 글로 한 판을 주고받는 개발용 뼈대이고, 모의 모델로만 돕니다. 음성, SQLite 저장, 실제 모델 연결은 다음 단계에서 붙입니다.

## 띄우기

```
npm install
npm run app:dev
```

서버(Hono, `127.0.0.1:8787`)와 화면(Vite)을 함께 띄웁니다. 화면 주소는 실행하면 나옵니다(보통 `http://127.0.0.1:5173/`).

- 모의 모델만 쓰고 `.env`를 읽지 않으므로 비용이 들지 않습니다. 상대의 답은 흐름을 확인하려고 만든 문장이라 뜻이 없습니다.
- 판은 메모리에만 남아 서버를 다시 띄우면 사라집니다.
- 서버 코드를 고치면 명령을 다시 띄웁니다. 화면 코드는 저장하면 바로 바뀝니다.

화면만 빌드하려면 `npm run app:build`를 씁니다. 결과는 `app/web/dist/`에 생기고 커밋하지 않습니다.

## 지키는 것

- **잰 상대와 배포한 상대가 같습니다.** 지시문과 판정은 `eval/src`의 코드를 불러 씁니다. 한 턴은 판정 실험과 같은 `runTurn`(`eval/src/dialogue.ts`)이 맡습니다.
- **판마다 방식을 숨깁니다.** 서버가 지시문 방식과 엔진 방식을 반씩 고르고, 방식과 판정과 장부를 화면에 보내지 않습니다. 사람 비교에서 어느 쪽인지 모른 채 토론하게 하려는 것입니다.
- **키는 서버에만 둡니다.** 화면은 모델을 직접 부르지 않습니다. 지금은 실제 모델 연결 자체가 없습니다.

## 구조

| 위치 | 하는 일 |
| --- | --- |
| `server/app.ts` | HTTP 주소. 웹 표준만 써서 배포처를 옮길 수 있습니다 |
| `server/games.ts` | 판 진행(시작, 한 턴, 끝내기). 턴 수와 글자 수 상한 |
| `server/store.ts` | 판 저장. 지금은 메모리 |
| `server/topics.ts` | 주제. 서비스용 주제 카드를 정하기 전까지는 판정 실험의 질문과 입장 카드를 씁니다 |
| `server/models.ts` | 모의 모델 |
| `server/contract.ts` | 화면과 서버가 주고받는 모양 |
| `web/` | React 화면 |
| `web/src/turn-flow.ts` | 한 턴 보내기. 응답을 잃었을 때 판을 다시 불러 서버와 맞춥니다(검사 있음) |
| `dev.ts` | 개발 명령(`npm run app:dev`) |
| `tests/` | 서버와 한 턴 보내기의 검사. `npm test`에 들어 있습니다 |

## 주소

| 요청 | 하는 일 |
| --- | --- |
| `GET /api/topics` | 주제 목록과 모델 종류(모의 모델인지) |
| `POST /api/games` `{ topicId }` | 판 시작. 사용자의 첫 말과 상대의 첫 발언이 옵니다 |
| `GET /api/games/:id` | 판 다시 불러오기 |
| `POST /api/games/:id/turns` `{ text }` | 한 턴. 상대의 답이 옵니다 |
| `POST /api/games/:id/end` | 판 끝내기 |

- 한 판은 30턴(판정 실험이 잰 길이)까지, 한 턴은 1,000자까지 받습니다.
- 쓰는 요청은 JSON(`content-type: application/json`)으로만 받습니다. 다른 사이트가 브라우저로 보내는 단순 요청을 막으려는 것입니다.
- 같은 판의 턴과 끝내기는 한 번에 하나씩 처리하고, 처리 중에 온 요청은 409로 막습니다. 서버가 하나일 때만 지켜지므로, 배포할 때 저장소에서 다시 지킵니다.
- 메모리 저장소는 판이 1,000개를 넘으면 가장 먼저 만든 판부터 지웁니다.
