# voice-screen: 음성으로 한 판(화면)

`screen`과 같이 앱을 빈 포트에 모의 모델로 띄우고 창 없는 Chrome으로 누른다. 다른 점은 하나다. 페이지 스크립트보다 먼저 도는 스크립트가 브라우저의 음성 인식(`SpeechRecognition`, `webkitSpeechRecognition`)과 음성 합성(`speechSynthesis`, `SpeechSynthesisUtterance`)을 가짜로 바꾼다. 브라우저 API 경계의 모의라서, 앱의 코드(`browser-voice.ts`부터 화면까지)는 그대로 돈다.

- 가짜 인식기: [말하기]로 start되면 여정이 넣어 둔 글 하나를 중간 결과로 내고 기다린다. [말 마치기]로 stop되면 그 글을 확정 결과로 내고 끝난다. 기기 안 인식(`available`, `install`)은 바로 된다고 답한다.
- 가짜 합성기: 한국어 기기 목소리 하나를 내놓는다. speak한 글을 적어 두고 차례로 start와 end를 낸다. 소리는 내지 않는다.
- 네 이름을 읽은 횟수와 함수를 부른 횟수를 센다(`window.__fakeVoice.log`). 실제 마이크와 소리는 쓰지 않는다.

| 단계 id | 사용자 행동 | 보여야 하는 것 |
| --- | --- | --- |
| `app` | 앱을 띄운다 | `screen`의 `app`과 같다 |
| `start` | 첫 주제를 왼쪽 '대체로'로 시작한다 | [음성으로 하기]가 있다. 켜기 전에는 인식기를 만들지 않고, 기기 안 인식을 묻지 않고, 합성기에 아무것도 보내지 않는다 |
| `voice-on` | [음성으로 하기] | "말소리는 이 기기 안에서 글로 바뀝니다.", [말하기]가 눌리고 [음성 끄기]가 있다. 합성기의 첫 글은 소리 크기 0의 빈 글이고, 그 뒤로 상대의 첫 발언을 글자까지 그대로 기기 목소리로 받는다 |
| `say-first` | 말하기('첫째') → [말 마치기] | 듣는 중에 "듣는 중: 첫째". 입력 칸 '첫째', 알림 "인식한 글을 입력 칸에 넣었습니다." 인식기는 ko-KR, 기기 안, 중간 결과 켬 |
| `say-again` | 손대지 않고 말하기('둘째') → [말 마치기] | 입력 칸이 '둘째'로 바뀐다(2026-11-23 결정). 알림 "앞서 인식한 글을 새로 인식한 글로 바꿨습니다." |
| `edit-then-say` | 입력 칸 끝에 ' 그리고'를 친 뒤 말하기('셋째') → [말 마치기] | 입력 칸 '둘째 그리고 셋째'(2026-11-24 결정). 알림 "쓰던 글은 두고 인식한 글을 끝에 붙였습니다." |
| `send-voice` | [보내기] | 판 파일의 턴 1이 user_text '둘째 그리고 셋째', input voice, redone 1(다시 말해 바꾼 한 번). 합성기가 상대의 답을 글자까지 그대로 받는다 |
| `off-while-listening` | 말하기('넷째') → [말 마치기] → 다시 말하기('다섯째')가 듣는 중일 때 [음성 끄기] | 입력 칸이 '넷째 다섯째'다. 끄면서 넘긴 글은 입력 칸이 직전 인식 글 그대로여도 바꾸지 않고 끝에 붙인다(PR #30). [말하기]가 사라지고 [음성으로 하기]가 돌아온다 |
| `send-after-off` | [보내기] | 판 파일의 턴 2가 user_text '넷째 다섯째', input voice, redone 0. 음성이 꺼져 있어 0.5초를 기다려도 합성기에 간 글이 없다 |
| `embedded` | User-Agent를 VS Code(`Electron/` 포함) 꼴로 바꿔 화면을 새로 열고 지난 판의 [이어 하기] | 음성 줄이 "이 창은 앱 안에 들어 있는 브라우저라 음성 기능을 쓸 수 없습니다. Chrome에서 이 주소를 열면…"이고 [음성으로 하기]가 없다(PR #29, #31). 이 페이지에서는 가짜 인식기와 합성기의 네 이름을 한 번도 읽지 않는다. 여정 내내 화면의 예외와 console.error가 없다 |

## 확인한 변이

여정이 잡아야 할 고장을 일부러 넣고 돌려 FAIL을 봤다(2026-11-25, 작업 트리는 되돌렸다).

- `app/web/src/dictation.ts`의 `takeDictation`이 `appendOnly`를 무시하면 `off-while-listening`에서 FAIL: `'다섯째' !== '넷째 다섯째'`.
- `app/web/src/use-voice.ts`가 앱 안 브라우저에도 음성 기능을 넘기면 `embedded`에서 FAIL: `앱 안 브라우저의 안내 대신 보인 음성 줄: 음성으로 하기 말소리는 브라우저의 음성 인식이 글로 바꿉니다. …`.

## 이 여정이 증명하지 않는 것

- 실제 인식기의 정확도와 쉼에서 끊기는 때, 실제 목소리와 읽는 속도, 실제 마이크와 권한 창. 사람이 Chrome에서 직접 본다(`app/README.md`의 '확인한 것과 확인하지 못한 것').
- 기기 안 인식 팩 내려받기와 그 뒤 브라우저를 다시 열어야 하는 흐름, 기기 밖 목소리 고르기. 가짜는 늘 바로 된다고 답하고 기기 목소리를 하나만 내놓는다. 판단 로직은 `app/tests/voice-control.test.ts`, `listen.test.ts`, `speak.test.ts`가 가짜 포트로 검사한다.
- 실제 Electron 안에서 페이지가 닫히는지. 이 여정은 User-Agent만 바꾼 Chrome이다.
- 듣기의 조용함 시간 제한(2.5초). 여정은 [말 마치기]나 [음성 끄기]를 그보다 먼저 누른다.
