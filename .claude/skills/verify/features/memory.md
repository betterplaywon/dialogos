# memory: 같은 주제로 두 판, 넘긴 기록 고치고 지우기(화면)

`screen`과 같이 앱을 빈 포트에 모의 모델로 띄우고 창 없는 Chrome으로 누른다. 앱의 환경에서 `APP_*`를 지우므로 판의 방식은 기본값인 엔진이고 기억이 켜져 있다(`app/server/dev-setup.ts`). 같은 주제로 두 판을 하면서, 첫 판이 끝 기록 때 남긴 기억이 둘째 판의 턴마다 상대에게 넘어가는지 화면과 판 파일(`app-01.sqlite`)로 본다. 판 파일의 기억 표는 `memories`, 턴마다 넘긴 기억의 id는 `turns.memory_ids`다.

| 단계 id | 사용자 행동 | 보여야 하는 것 |
| --- | --- | --- |
| `app` | 앱을 띄운다 | `screen`의 `app`과 같다 |
| `first-game` | 첫 주제를 왼쪽 '대체로'로 시작해 세 턴(짧은 글, 긴 글, 같은 짧은 글)을 보낸다 | 기억이 없어 답 아래 넘긴 기록이 없다. 판 파일의 `games.memory` 1, 세 턴의 `memory_ids`가 모두 `[]` |
| `record` | [끝내기] → 사후 입장 오른쪽 '대체로', 훈계 문항 '토론' → [기록 남기기] | 판 파일에 그 판의 기억이 4개 이상(한 턴에 넘기는 3개보다 많아야 지운 자리를 채우는 것까지 본다). 모두 첫 판, 같은 주제, side 0, 고친 적 없음. 첫 기억은 주장이고 첫 턴에 친 글을 담는다. 생각을 바꿨으니(-1 → 1) 바뀐 생각 기억이 있다 |
| `list` | [목록으로] | '내 기억' 절에 그 주제의 묶음 하나. 항목(종류, 글)이 판 파일의 기억과 같은 차례 |
| `start` | 같은 주제의 [이 주제로] | 시작 화면에 '이 주제의 지난 기록'과 "상대에게 최근 3개까지 넘깁니다". 항목이 판 파일과 같다 |
| `passed` | 같은 입장으로 둘째 판을 시작해 짧은 글 한 턴 → 답 아래 [이 답을 만들 때 넘긴 기록 3개] | 처음에는 접혀 있다. 판의 첫 발언 아래에는 없다. 펼치면 최근 기억 3개이고, 판 파일의 턴 1 `memory_ids`가 같은 id 셋이다 |
| `edit` | 넘긴 첫 기록의 [고치기] → 입력 칸의 글을 모두 골라 새 글을 쳐서 [저장] | 입력 칸은 지금 글로 시작한다. 그 자리에 고친 글과 '고침'. 판 파일의 그 기억 글이 바뀌고 `edited_at`이 생긴다 |
| `delete` | 넘긴 둘째 기록의 [지우기] → 그 자리의 물음 "이 기록을 지울까요? 상대에게 더 넘기지 않습니다. 판 기록은 남습니다." → [정말 지우기] | 그 자리가 "지운 기록 기억만 지웠습니다. 판 기록은 남습니다."로 바뀐다. 판 파일에서 그 기억만 빠지고, 지운 글이 화면 어디에도 없다 |
| `next-turn` | 짧은 글로 한 턴 더 → 답 아래 넘긴 기록을 펼친다 | 넘긴 기록 3개: 고친 첫 기록(고침), 그리고 지운 자리를 채운 다음 기억 둘. 판 파일의 턴 2 `memory_ids`가 같고 지운 id가 없다. 고친 때가 턴 2보다 앞이다(서버는 턴마다 기억 표의 지금 글을 넘기므로, 턴 2에 넘긴 글은 고친 글이다) |
| `reopen` | 페이지를 새로 열고 지난 판의 [이어 하기] → 두 답 아래 넘긴 기록을 펼친다 | 화면이 덮어 둔 것 없이 서버가 보낸 판 그대로다. 턴 1은 고친 글(고침), "지운 기록"(글 없음), 그대로인 기록. 턴 2는 `next-turn` 때와 같다. 지운 글과 고치기 전 글이 화면에 없다 |
| `list-after` | [목록으로] | '내 기억'에 고친 글(고침)이 있고 지운 기억은 없다 |
| `db` | 판 파일을 읽는다 | `memories`가 화면에서 본 것과 같다(고친 줄 하나, 지운 줄 없음). `games` 2행, 둘 다 `memory` 1. 둘째 판 턴의 `memory_ids`가 화면의 넘긴 기록과 같다. 기억을 지워도 첫 판의 턴 원문은 그대로다. 여정 내내 화면의 예외와 console.error가 없다 |

이 Mac에서 단계 합계 약 10초(2026-11-26, 잇달아 세 번 잰 값 9.7초, 9.8초, 9.5초). `npm ci` 바로 뒤의 첫 실행은 11.2초였다.

## 확인한 변이

여정이 잡아야 할 고장을 일부러 넣고 돌려 FAIL을 봤다(2026-11-26, 작업 트리는 되돌렸다).

- `app/server/games.ts`의 턴이 넘긴 기억의 id를 남기지 않으면(`memoryIds: []`) `passed`에서 FAIL: `판 파일의 턴 1 memory_ids`. 답 아래의 넘긴 기록은 턴 응답으로 그대로 보이므로, 화면만 봐서는 잡지 못한다.
- `app/web/src/memories.tsx`가 지운 뒤에도 기록을 글째로 두면 `delete`에서 FAIL: `10초를 기다려도 지운 기록으로 바뀌지 않는다`.
- `app/server/sqlite-store.ts`의 `deleteMemory`가 지웠다고 답하고 줄을 남기면 `delete`에서 FAIL: `판 파일의 기억(지운 것만 빠진다)`. 화면은 '지운 기록'으로 바뀌어 화면만 봐서는 잡지 못한다.
- `app/server/sqlite-store.ts`의 `editMemory`가 고친 시각만 남기고 글을 그대로 두면 `edit`에서 FAIL: `판 파일의 기억 글`.
- `app/web/src/App.tsx`의 `passedAtMessages`가 넘긴 기록을 한 답 앞에 붙이면 `passed`에서 FAIL: `판의 첫 발언 아래에 넘긴 기록이 있다`.

## 이 여정이 증명하지 않는 것

- 상대의 지시문에 기억 글이 실제로 들어가는지. 모의 모델의 답은 기억을 드러내지 않는다. 여정은 판 파일의 턴 `memory_ids`와 기억 표로 무엇을 넘겼는지 본다. 지시문의 기억 칸과 판정기에 넘기지 않는 것은 `app/tests/memory.test.ts`(호출을 기록하는 가짜 모델)와 `eval/tests/prompts.test.ts`, `dialogue.test.ts`가 검사한다.
- 기억이 꺼진 판(`APP_MODE=random`, 눈가림 비교). 여정은 앱의 환경에서 `APP_*`를 모두 지워 엔진 방식만 띄운다. `app/tests/memory.test.ts`가 맡는다.
- 다른 주제와 다른 사용자의 기억이 넘어가지 않는 것, 고친 글의 글자 수 제한과 한 줄로 펴기, 기억을 만드는 규칙의 글. `app/tests/memory.test.ts`, `store.test.ts`가 맡는다.
- 좁은 화면의 배치, 밝은 화면과 어두운 화면을 견주기. 화면 사진은 창 없는 Chrome의 기본 색 설정 하나로 찍는다.
- 실제 모델의 답. 모의 모델의 답은 흐름을 확인하려고 만든 문장이다.
