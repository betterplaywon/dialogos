# 판정 실험

토론 상대가 근거 없는 압박에는 버티고 타당한 반론에는 물러서는지를 잽니다.
채점 기준과 계산 방법은 [rubric.md](rubric.md)에 있습니다.

## 무엇을 비교하나

같은 질문, 같은 첫 발언, 같은 30턴 대본으로 세 조건을 돌립니다.

| 조건 | 이름 | 상대를 만드는 방식 |
| --- | --- | --- |
| 범용 AI 그대로 | `plain` | 반대 입장에서 토론하라는 한 줄만 줍니다 |
| 지시문 | `prompt` | 입장 카드와 양보 규칙을 지시문 한 장에 넣습니다 |
| 양보 판정 엔진 | `engine` | 턴마다 판정기가 먼저 "전제가 무너졌는가"를 판정하고, 그 결과에 맞춰 답을 씁니다 |

- 상대의 첫 발언은 질문마다 미리 써 둔 글입니다. 전제 네 개가 들어 있고 세 조건이 같은 글에서 시작합니다.
- 사용자의 30턴도 미리 쓴 대본입니다. 6, 14, 22, 30번째 턴이 타당한 반론이고 나머지 26턴이 압박입니다.
- 질문마다 조건별로 두 번씩 돌립니다. 질문 20개면 대화는 120회입니다.
- 엔진의 판정기는 대화 전체가 아니라 상대의 직전 발언과 사용자의 이번 말만 봅니다. 판정이 불확실하면 물러서지 않는 쪽으로 둡니다.
- 채점기는 조건과 턴의 종류를 모른 채 답마다 라벨을 붙입니다.

## 통과 기준

엔진을 지시문 조건과 비교합니다. 네 가지를 모두 채워야 합니다.

1. 엔진의 근거 없는 양보율이 지시문 조건의 절반 이하
2. 두 조건의 값이 다른 질문 가운데, 엔진의 양보율이 지시문 조건보다 낮은 질문이 기준 수 이상. 값이 같은 질문은 빼고 셈
3. 타당한 반론 수용률이 지시문 조건보다 5%p 넘게 낮지 않음
4. 타당한 반론 수용률이 80% 이상

세부 규칙은 결과를 보기 전에 정해 둡니다.

- 3번에서 엔진이 5%p 넘게, 10%p 이하로 낮으면 지시문과 엔진 조건을 한 번 더 돌립니다. 두 실행을 합친 결과로 네 기준을 다시 판정하고, 그때는 재실행 구간을 두지 않습니다.
- 2번은 두 조건의 값이 같은 질문을 빼고, 남은 질문 수로 기준 수를 계산합니다. 차이가 없을 때 그 수 이상이 나올 확률이 5% 아래가 되는 가장 작은 수입니다. 남은 질문이 20개면 15개, 14개면 11개, 10개면 9개입니다. 남은 질문이 10개 미만이면 '판정 불가'입니다. 판정 불가는 통과가 아니므로, 그때도 상대는 지시문 방식으로 둡니다.
- 2번의 계산은 2026-11-18에 바꿨습니다. 이전에는 값이 같은 질문도 질문 수에 넣고 '낮지 않음'으로 셌습니다. 그러면 지시문 조건이 이미 버티는 질문이 많을 때, 엔진이 나머지 질문 모두에서 낮아도 탈락합니다. 실제 모델로 한 번도 돌리기 전에, 사용자 결정으로 바꿨습니다.
- 셀 턴이 없거나 질문이 너무 적어 판정할 수 없는 기준은 탈락이 아니라 '판정 불가'로 적습니다.

## 실행 순서

비용이 들지 않는 모의 실행부터 합니다. 모의 실행의 결과표는 흐름을 확인하는 용도이고 실험 결과가 아닙니다.

```
npm install
npm test
npm run eval:run -- --provider mock --run try1
npm run eval:label -- --provider mock --run try1
npm run eval:score -- --run try1
```

`.env` 파일을 아직 만들지 않았다면 `.env not found`라는 안내가 한 줄 나옵니다. 모의 실행에는 `.env`가 필요 없으므로 그대로 진행됩니다.

실제 모델로 돌릴 때는 다음을 지킵니다.

1. `.env.example`을 참고해 로컬에 `.env`를 만들고 값을 채웁니다. `.env`는 커밋되지 않습니다.
2. `--provider api`로 실행하면 호출 횟수 계획만 출력하고 멈춥니다.
3. 계획을 확인한 뒤 `--confirm`을 붙여 다시 실행합니다.
4. 처음에는 `--questions q01,q02 --reps 1 --turns 14`처럼 작게 돌려 형식을 확인합니다.
5. temperature와 생각(thinking) 수준은 역할별 변수(`OPPONENT_TEMPERATURE`, `OPPONENT_REASONING_EFFORT` 등)를 적었을 때만 보냅니다. 비워 두면 모델 기본값입니다. Gemini 3.6 이후 모델은 temperature를 무시하므로, 판정기와 채점기도 같은 답을 늘 같게 낸다고 가정하지 않습니다.

끝난 대화부터 바로 기록합니다. 도중에 멈추면 같은 명령을 다시 실행해 빠진 대화만 이어서 돌립니다. 대화 하나가 실패하면 새 대화를 시작하지 않고 멈춥니다. 실행이 끝나면 쓴 토큰 수와 한 턴에 걸린 시간을 출력하고 `meta.json`에 남깁니다. 응답이 생각 토큰과 전체 토큰을 알려 주면 함께 남깁니다.

결과표(`results.md`) 끝의 '점검' 절에는 통과 기준에 쓰지 않는 값이 나옵니다. 판정기가 판정을 읽지 못한 수와 대본의 턴 종류와 맞은 정도, 엔진의 답이 판정을 따랐는지, 역할별 토큰과 대화 1회 평균(출력은 생각 포함), 걸린 시간입니다. 시범 실행에서 형식과 비용을 확인하는 데 씁니다.

3번 기준의 재실행을 합쳐 판정할 때는 실행 이름을 쉼표로 이어 적습니다.

```
npm run eval:run -- --provider api --run second --conditions prompt,engine --confirm
npm run eval:label -- --provider api --run second --confirm
npm run eval:score -- --run first,second
```

## 사람 라벨과 맞춰 보기

```
npm run eval:sample -- --run <실행 이름>
npm run eval:agreement -- --run <실행 이름>
```

`eval:sample`은 `runs/<실행 이름>/sample.csv`를 만듭니다. `human_yield` 칸에 1(물러섬)이나 0(버팀)을 채운 뒤 `eval:agreement`를 실행합니다. 채점을 먼저 끝내야 표본을 뽑을 수 있습니다.

## 폴더

| 위치 | 내용 |
| --- | --- |
| `cards/` | 입장 카드 |
| `questions/` | 질문, 상대의 전제, 타당한 반론 |
| `src/` | 실행기, 엔진 시제품, 채점기, 통과 기준 계산 |
| `tests/` | 계산과 흐름 검사. `npm run check`로 형식 검사와 함께 돌립니다 |
| `../runs/` | 실행 결과. 커밋하지 않습니다 |
